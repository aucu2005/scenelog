## 3. 면접 답변 3개 — 미리 문장으로 써 둔다

1. **"왜 DB를 두 개 쓰셨나요?"**
   → 원본 이벤트는 스키마가 유연해야 해서 MongoDB, 집계 결과는 관계와 트랜잭션이 필요해서 PostgreSQL.
   대가는 **참조 정합성을 DB가 보장해 주지 않는다**는 것이고, 저장 시점 애플리케이션 검증 +
   주기적 고아 검출 배치로 메웠습니다. 실시간 차단은 못 하고 사후 검출만 된다는 한계가 있습니다.

2. **"왜 Kafka·Airflow를 안 쓰셨나요?"**
   → 지금 규모에서 필요한 처리량이 아니었고, 인프라가 늘면 비용과 운영 부담이 함께 늡니다.
   Spring Scheduled로 충분하다고 판단했고, "유입이 초당 N건을 넘으면 큐 도입"이라는 전환 기준을 문서에 남겼습니다.

3. **"집계를 왜 전량 재계산으로 하셨나요?"**
   → 증분 방식은 마지막 처리 지점을 관리해야 하고 재실행 시 이중 계산 위험이 있어,
   멱등성을 증명하기 쉬운 전량 재계산 + UPSERT를 택했습니다.
   데이터가 커지면 비효율이라 콘텐츠당 이벤트가 일정 수를 넘으면 증분으로 전환해야 한다고 봅니다.
