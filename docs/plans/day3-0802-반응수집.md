# 8/2 — 반응 이벤트 수집 API + 시뮬레이터

## 목표

시청자가 "몇 초 지점에 어떤 반응을 눌렀는지"를 받아 MongoDB에 쌓고,
프론트엔드가 없으므로 **시뮬레이터가 그 API를 호출해** 데이터를 만들어낸다.

## 산출물

- [ ] `POST /api/sessions/{id}/reactions` — 배치 등록, 검증 5종 동작
- [ ] `POST /api/admin/simulate` — 시연 모드로 이벤트 수천 건 생성
- [ ] MongoDB `reaction_events`에 데이터 적재 확인
- [ ] 같은 배치를 두 번 보내도 **중복이 쌓이지 않음**(멱등)

## 작업 순서

### 1단계 — 시뮬레이터 순수 로직 (TDD) ★ 여기부터
[core-five-TDD.md](core-five-TDD.md)의 **Task 3**을 수행한다.
`ReactionType` · `ReactionEvent` · `Peak` · `Scenario` · `ReactionSimulator`가 만들어진다.

**각본(Scenario)이 곧 정답지**라는 게 핵심이다. 내일(8/3) 검출기가 이 정답을 찾아내는지로 정확도를 측정한다.

### 2단계 — MongoDB 저장 연동

`ReactionEvent`에 `@Document(collection = "reaction_events")` 부착 + `ReactionEventRepository`(MongoRepository).

**인덱스 2개를 반드시 만든다** (내일 성능 측정의 대상):
- `{contentId: 1, offsetSec: 1}` 복합 — 집계 범위 조회 경로
- `{clientEventId: 1}` unique — 멱등키

> 인덱스는 `@CompoundIndex`/`@Indexed`로 선언하거나 mongosh로 직접 생성한다.
> **8/4에 "인덱스 없을 때 vs 있을 때"를 비교할 것이므로, 언제 만들었는지 기억해 둔다.**

### 3단계 — 수집 API (`reaction/ReactionController.java` + `ReactionService.java`)

`POST /api/sessions/{sessionId}/reactions` — 요청 본문은 이벤트 배열.

**검증 5종** (이게 이 API의 핵심):

| 검증 | 실패 시 |
|---|---|
| 세션이 존재하고 **요청자 소유**인가 | 403 |
| `offsetSec >= 0` 이고 `<= duration_sec` 인가 | 400 |
| `reactionType`이 enum에 있는가 | 400 |
| 배치 크기 ≤ 500 | 400 |
| `clientEventId` 중복 아닌가 | 무시하고 통과(멱등) |

> 소유 검증은 `SessionService.end()`에 이미 구현된 패턴을 재사용한다.
> **이것이 기획서 §5.4의 "애플리케이션이 FK를 대신한다" 부분이다** — MongoDB는 참조 정합성을 보장해 주지 않으므로.

### 4단계 — 시뮬레이터 REST 경로 (`reaction/sim/SimulateController.java`)

`POST /api/admin/simulate` (ROLE_ADMIN) → `ReactionSimulator.generate()` 결과를
**REST API를 통해** 등록한다. DB에 직접 넣지 않는 이유: 위 검증 5종이 실제로 도는지 함께 확인되기 때문.

## 검증

```
docker exec scenelog-mongo mongosh scenelog --quiet --eval "db.reaction_events.countDocuments()"
docker exec scenelog-mongo mongosh scenelog --quiet --eval "db.reaction_events.findOne()"
```

**멱등 확인**: `POST /api/admin/simulate`를 **같은 파라미터로 두 번** 호출 → 건수가 2배가 되지 않아야 한다.

## 🚨 손절 기준

| 상황 | 대응 |
|---|---|
| MongoDB 연동이 막힘 | 반응 이벤트도 PostgreSQL 테이블로. 폴리글랏 어필 포기, 파이프라인 유지 |
| 멱등 처리가 막힘 | unique 인덱스만 걸고 중복 시 예외를 잡아 무시. 완벽한 배치 멱등은 포기 |
| 시뮬레이터를 정교하게 만들고 싶어짐 | **즉시 멈춘다.** 필요한 건 ①배경 노이즈 ②정답 피크 둘뿐이다 (기획서 §5-B-7) |
