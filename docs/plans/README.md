## 사용 규칙

1. **아침에 그날 문서를 열고, 산출물 체크박스를 목표로 삼는다.**
2. **각 문서의 🚨 손절 기준을 넘기면 즉시 다음으로 넘어간다.** 판단을 미루는 것이 가장 큰 손해다.
3. **끝나면 `docs/dev-log.md`에 3줄 기록** — 한 일 / 만난 문제 / 내일 할 일.
4. 문제를 겪었으면 `docs/troubleshooting/`에 **이슈·원인·대응** 형식으로 승격한다. 이게 자격요건 8의 증거다.
5. **매일 최소 1회 커밋 + push.** 연속 커밋 히스토리 자체가 평가 항목이다.

## 우선순위 — 시간이 부족할 때 버리는 순서

기획서 §0-0-C의 최종 산출물 6개가 기준이다:

- [ ] 접속되는 URL · [ ] 연속 커밋 · [ ] 비개발자용 README
- [ ] 숫자 3개 · [ ] 트러블슈팅 로그 3~5건 · [ ] 면접 답변 3개

**어떤 작업이 이 6개에 기여하지 않으면 하지 않는다.**
기능 개수·코드의 아름다움·최신 기술은 목록에 없다.

만약 남은 날이 3일뿐이라면 → **URL + 로그 3건 + 숫자 1개.** 기능은 회원가입과 조회만.
