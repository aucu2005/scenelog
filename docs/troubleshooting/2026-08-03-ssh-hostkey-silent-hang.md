# "빌드가 안 끝난다" — 진범은 성능이 아니라 SSH 호스트 키 프롬프트였다

> 트러블슈팅 로그 8호 · 2026-08-03 · 대시보드 재배포 중. **증상에서 가장 그럴듯한 가설 3개가 전부 틀렸던 사건**

## 이슈

대시보드 재배포(`git pull && docker compose --profile app up -d --build`)를 SSH로 실행했는데:

- 20분이 지나도 루트가 옛 버전(403) 그대로 — 빌드가 끝나지 않는 것처럼 보임
- 진단용 SSH 접속조차 몇 분씩 무응답
- 그런데 **HTTP(8080)는 즉답** — 서버가 죽은 건 아님

## 기각된 가설들 (순서대로)

| 가설 | 근거처럼 보였던 것 | 기각 근거 |
|---|---|---|
| ① 메모리 스래싱 (옛 앱 JVM + 빌드 JVM 공존) | RAM 1GB에 두 JVM이면 그럴 만함 | 재부팅 후 **깨끗한 상태에서도 SSH만 계속 무응답** |
| ② ACPI 재부팅 무시 (커널이 wedged) | reboot 후에도 증상 동일 | force stop/start(하이퍼바이저 전원 차단) 후에도 동일 |
| ③ CPU 크레딧 고갈 (t3 버스트 소진) | 장시간 빌드 = 크레딧 소모 | `unlimited` 모드 + 잔량 15 확인 |

## 진범

**Elastic IP로 주소가 바뀐 뒤 첫 SSH부터, 모든 SSH가 호스트 키 확인 프롬프트에서 멈춰 있었다.**

```
The authenticity of host '13.124.60.61' can't be established.
Are you sure you want to continue connecting (yes/no/[fingerprint])?   ← 여기서 무한 대기
```

- `known_hosts`는 **IP(호스트명) 기준**이다. 같은 서버여도 EIP로 주소가 바뀌면 "처음 보는 호스트"
- 자동화 환경은 stdin이 닫혀 있어(NonInteractive) 프롬프트 응답을 영원히 기다린다 —
  에러도 없고 출력도 없는 **완전한 침묵**
- 그래서 "빌드 중"으로 보였지만 실제로는 **빌드가 시작조차 안 됐다**
  (배포 후 EC2의 git이 이틀 전 커밋에 머물러 있던 것이 결정적 증거)

결정적 단서는 계층 분리였다: `Test-NetConnection`으로 **TCP:22 도달 성공**을 확인하는 순간,
"네트워크·서버 문제"가 전부 기각되고 "SSH 프로토콜 안쪽에서 멈춘다"만 남았다.

## 대응

```bash
ssh -o StrictHostKeyChecking=accept-new ...   # 새 호스트 키를 자동 수락 (기존 키 변조는 여전히 거부)
```

적용 즉시 연결 1초, 빌드 정상 시작 → 배포 완료.

## 재발 방지

1. **자동화에서 쓰는 모든 ssh에 `-o StrictHostKeyChecking=accept-new`를 기본으로** —
   특히 IP가 바뀔 수 있는 환경(EIP 부착, 인스턴스 재생성)
2. "느리다/안 끝난다"는 증상에서 **출력이 0바이트면 성능 가설보다 '입력 대기' 가설을 먼저** —
   성능 문제는 보통 느리게라도 출력이 나온다
3. 원격 명령의 출력을 `| tail`로 감싸면 완료까지 아무것도 안 보인다 — 진행 확인이 필요한
   장기 명령은 스트리밍되게 두거나 `grep --line-buffered`로 필터링
4. 가설 검증은 **계층을 잘라서** (TCP 도달 → 프로토콜 → 앱): `Test-NetConnection`이 3개의
   그럴듯한 가설을 한 번에 정리했다
